Что осталось на этапе:

## Как я тестирую (без запуска Minecraft в песочнице)

В песочнице **нет GPU, нет экрана и закрыты** `piston-data.mojang.com`, `maven.fabricmc.net`,
`services.gradle.org`. Поэтому:

| Задача | Способ |
|---|---|
| Скомпилировать мод | **GitHub Actions** (Java 25 + интернет есть). Пушу ветку → читаю `annotations` через `gh api` |
| Ловить ошибки API 26.3 | логи CI + сверка с исходниками 26.3 на GitHub |
| Автотесты логики | Fabric **GameTest** в CI (headless) |
| Кадры, FPS, состояние | **BotLab** (`lab/`) — дашборд, кадры 1/сек, сценарии, отчёты |
| Ручной тест | на ПК: `./gradlew runClient`, мод + BotLab |

> Java 25 в песочнице **установлена** (JDK из PyPI `jdk4py`), но Gradle/Loom/Minecraft
> скачать нельзя — поэтому сборка идёт в CI, а не локально. Это осознанное ограничение,
> а не отговорка: результат тот же — бинарник и логи сборки.

## Ближайшие шаги (по порядку)

1. Добить сборку в CI до зелёной.
2. Добавить мод-часть телеметрии: `com.botmod.lab.*` (HTTP на `127.0.0.1:17777`).
3. Соединить BotLab с модом: бот-карточки, события урона, режимы.
4. Написать GameTest: спавн бота → дуэль → проверка, что цель получает урон.
5. Снять кадры через BotLab и приложить к отчёту.
6. Расширить AI: стрейф-паттерны, комбо, реакция на щит.

## Известные ограничения

- Мод пока **не запускался в реальном клиенте** — только компилируется в CI.
  Первый живой прогон — на ПК (`./gradlew runClient`) или в CI с Xvfb (попробуем на этапе 4).
- Бот — `PathfinderMob` с моделью игрока, а не настоящий `ServerPlayer`.
  Плюс: полный контроль AI и нет возни с авторизацией. Минус: нет ванильной
  `Player#attack` (криты/зачарования считаем сами).
- Броня рендерится (используется `HumanoidMobRenderer`), но скин пока один —
  свой PNG. Подгрузка скинов игроков — этап 6.
